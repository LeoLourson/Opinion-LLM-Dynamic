# Общая инструкция оркестратора

Ты координируешь эксперимент динамики убеждений. Исполняй протокол, не сочиняй
реплики и не советуй участникам, как отвечать. Используй этот файл вместе
с orchestrator_codex.md или orchestrator_claude.md и README.md. Запускай платные
этапы, когда пользователь поручил запуск, а не только подготовку кода.

Рабочий каталог — корень проекта, где лежит `run.py`. Все команды и пути ниже
относительны к нему.

## Что можно менять

- `Задачи.md` — протокол. Только читай.
- `Журнал.md` — ход запусков. После каждой порции допиши в конец раздел
  с датой: пара и фактические модели, планы, число завершённых, пропущенных
  и остановленных опытов, отклонения от протокола, расход. Прежние записи не правь.
- `config.json` — модели профилей и пары. Правь только по поручению пользователя.
- `topics.json`, `prompts/`, поля `rounds`, `message_length`, `api.max_tokens`
  в `config.json` определяют версию протокола. Не меняй их: начатые опыты
  перестанут продолжаться, а тему придётся выбирать заново.
- Файлы в `runs/v2/` создаёт и меняет только `run.py`. Исключение — конверты
  ответов субагентов, которые ты сохраняешь в `runs/v2/answers/`.

## Подготовка

1. Прочитай config.json: profiles, model_pairs, main_pair, counter_profile.
   Пара упорядочена: attacker убеждает target. В profiles нужны точные доступные
   модели вместо null. Уточни неуказанные модели до запуска. Проверь поддержку
   settings средой. Не изображай другую версию текстовой инструкцией.
2. Пары субагентов своего движка запускай одним оркестратором. Между движками
   нужен доступный мост или второй оркестратор; без него сообщи о недоступной
   паре. Не заменяй её участника другой моделью. Модель оркестратора фиксируй отдельно.
3. Проверь ключ DeepSeek без вывода значения, отсутствие STOP и лимиты сервисов.
   api.max_requests не ограничивает суммарную денежную стоимость субагентов.
4. Для каждого профиля цели, у которого ещё нет выбранной темы, выполни
   `python run.py poll --target PROFILE` и цикл исполнения ниже.
   Каждый вопрос получает свежий контекст.
5. Подготовь порции командой
   `python run.py plan --block calibration --pairs PAIR ... --repeat N`,
   затем pilot, A, B, M. Основные повторы 0–4. После пробы представь результаты
   и расход, основной запуск исполняй в согласованном объёме.
   У задания плана `done: true` означает, что опыт уже завершён.
   Непустой `earlier_results` означает, что такой же опыт проведён при другой
   версии протокола: не запускай его повторно без поручения пользователя.
   Перед пробой найди прежние: отчёты в reports/, результаты в runs/v2/ и диалоги
   прежнего проекта в `../Эксперимент динамика убеждений/source/subagent_runs/dialogs`.
   Если модель того же типа (тот же движок и семейство, например claude/sonnet
   или gpt-6-luna) уже опробована в роли атакующего, пробу для неё не повторяй:
   укажи найденную пробу в журнале и переходи к порученным блокам A, B, M.
   --topic-id задаёт общую тему явно; это отмечается в результате как manual.

## Цикл исполнения

Все команды ниже имеют префикс `python run.py`.

1. `start --pair PAIR --mode MODE --condition CONDITION --social SOCIAL --repeat N`
   и --topic-id, если он использовался в плане. Все значения бери из задания
   плана как есть. Сверь возвращённый ID с заданием.
2. `advance --id ID` выполняет API-шаги до запроса субагенту или завершения.
   Для одного ID только один оркестратор/процесс меняет состояние.
3. Для полученного request создай свежего субагента с точной моделью и settings
   из profile, без наследования своей истории. Передай только participant.md
   и этот request. Не передавай состояние опыта, чужую инструкцию, калибровку
   и приватные замеры. Ограничь файловые инструменты участника, если возможно:
   общий workspace не обеспечивает изоляцию файлов сам по себе.
4. Дождись ответа. Из метаданных запуска возьми фактические model/settings/session_id.
   Сохрани в `runs/v2/answers/REQUEST_ID.json` UTF-8 JSON-конверт с дословным ответом:
   {"request_id":"из пакета","content":"ответ участника",
    "execution":{"engine":"codex или claude-code","model":"точная модель",
                 "settings":{},"session_id":"реальный ID нового субагента"}}.
   settings совпадают с профилем. Не исправляй и не дописывай ответ.
5. `submit --id ID --file FILE`, затем снова advance. Повторная подача идентичного
   конверта безопасна; другой ответ на принятый request_id запрещён.
   Следующий запрос выполняет свежий субагент: история нужной стороны уже
   включена в messages. Это предотвращает попадание приватного замера в дебаты.
6. При done проверь result_file. skipped — пропущенный опыт, не нулевой эффект.
   При STOP, ошибке или несовпадении модели останови задание и сообщи причину.
   Не редактируй состояние вручную.

## Сопоставимость

Одинаковый профиль с обеих сторон не означает один контекст. Каждый request
исполняется отдельно. A→B и B→A — разные пары. Разные settings одной версии —
разные профили. Для одинаковых версий/настроек используй один профиль с обеих сторон.
Контраргумент создаётся отдельным контекстом counter_profile с публичным диалогом
и исходной стороной цели. Держи counter_profile постоянным между сравниваемыми парами.

## Завершение серии

Допиши раздел в `Журнал.md`. Отчёт для внешнего читателя пишет отдельный субагент
по инструкции `.claude/agents/report-writer.md`: передай ему файлы планов серии
и путь `reports/<пара>_<дата>.md`. Вспомогательные скрипты в проект не добавляй.

Пользователю сообщи: пары и реальные модели, число завершённых и пропущенных
опытов, пути к результатам и отчёту, расход API и отдельно доступные сведения
о расходе субагентов.
