# Динамика убеждений: диалоги модельных пар

Атакующая модель пытается изменить позицию модели-цели по спорному тезису;
мы измеряем сдвиг позиции. Протокол эксперимента описан в `Задачи.md`.
Этот файл о том, как устроен проект и как запускать опыты.

## Что где лежит

## Кто что делает

`run.py` ведёт опыт: хранит истории, сам вызывает DeepSeek и проверяет ответы.
Субагентов Codex и Claude Code он запускать не умеет. Это делает оркестратор —
сессия Codex или Claude Code, которой переданы `agents/orchestrator.md` и
`agents/orchestrator_codex.md` либо `agents/orchestrator_claude.md`. Оркестратор
получает от `run.py` запрос, запускает свежего субагента с `agents/participant.md`
и возвращает его ответ.

Каждый субагент исполняет один запрос в новом контексте; история его стороны
целиком лежит в `messages` запроса. Поэтому замер позиции задаётся на копии
истории и в следующие реплики не попадает, а одинаковая модель с двух сторон
не делит контекст.

## Модели и пары

- `profiles` — транспорт (`api` или `subagent`), движок, точная модель, `settings`.
- `model_pairs` — упорядоченные пары: `attacker` убеждает `target`. Обратное
  направление задаётся отдельной парой.
- `main_pair` — пара по умолчанию.
- `counter_profile` — модель, которая пишет контраргумент после диалога.

У профиля с `model: null` модель не выбрана; опыт с ним не начнётся. Недоступная
модель не заменяется другой под прежним именем. `settings: {}` означает настройки
среды по умолчанию. Пара между движками (Codex → Claude) требует, чтобы оркестратор
мог запускать оба.

## Запуск

Нужны пакет из `requirements.txt` и ключ `DEEPSEEK_API_KEY` в окружении.
Команды выполняются из корня проекта.

```powershell
python -m pip install -r requirements.txt
python -m unittest discover tests -v
```

Опрос тем для профиля цели:

```powershell
python run.py poll --target deepseek
python run.py advance --id ID
```

Состав порции. План ничего не запускает и не тратит:

```powershell
python run.py plan --block calibration --pairs haiku_to_deepseek
python run.py plan --block pilot --pairs haiku_to_deepseek
python run.py plan --block A --pairs haiku_to_deepseek --repeat 1
python run.py plan --block M --pairs claude_same claude_versions
```

Блоки: `calibration` — два контрольных диалога на цель, `pilot` — три условия,
`A` — 15 условий стратегии, `B` — 6 социальных вариантов, `M` — контроль на каждой
паре. Контрольный диалог входит в A, B и M с одним ID и проводится один раз.
Основные повторы имеют номера 0–4, пробные — от 100000. У задания `done`
показывает, что опыт завершён, а `earlier_results` перечисляет такие же опыты,
проведённые при другой версии протокола.

Один опыт:

```powershell
python run.py start --pair haiku_to_deepseek --condition emotion:anger --repeat 1
python run.py advance --id ID
```

`start` только создаёт состояние. `advance` исполняет шаги DeepSeek и останавливается,
когда нужен субагент: возвращает `request` и путь к его файлу. Оркестратор запускает
субагента и сохраняет ответ конвертом:

```json
{
  "request_id": "идентификатор из request",
  "content": "дословная реплика либо JSON замера в виде строки",
  "execution": {
    "engine": "claude-code",
    "model": "фактический идентификатор модели",
    "settings": {},
    "session_id": "реальный идентификатор нового субагента"
  }
}
```

```powershell
python run.py submit --id ID --file runs/v2/answers/REQUEST_ID.json
python run.py advance --id ID
```

Цикл повторяется до `done: true`. `stage: skipped` означает пропуск: цель три раза
подряд отметила позицию 0. `python run.py status --id ID` показывает стадию.

`--topic-id topic_05` в `plan` и `start` задаёт тему вручную вместо выбранной
опросом; в результате это отмечено как `topic_source: manual`.

## Версия протокола

`protocol` в каждом опыте — хеш файлов `topics.json`, `prompts/*.txt`,
`prompts/catalog.json` и полей `rounds`, `message_length`, `api.max_tokens`.
Правка любого из них меняет хеш: начатые опыты не продолжаются, выбранная тема
перестаёт действовать, новые опыты получают другие ID. Профили и пары в хеш
не входят, их можно добавлять между порциями.

До 12 октября 2026 хеш включал весь `config.json` и инструкции оркестратору,
поэтому у завершённых серий три значения: `c3f2813ed80b`, `33733a4ff3e3`,
`75c0cc31e908`. Тексты диалога у них те же, что у текущего `cd0c014e5399`.

## Остановка, восстановление, расход

- Файл `STOP` в корне проекта прекращает новые шаги. Уже отправленный запрос
  к API может завершиться.
- Состояние сохраняется после каждого принятого ответа. После обрыва повторите
  `advance` или тот же `submit`. Другой ответ на принятый запрос, чужой
  `request_id`, другая модель и повторный `session_id` отвергаются.
- Одно состояние меняет один процесс одновременно. Вручную состояния не правятся.
- Ответы API кэшируются по ID запроса и повторно не оплачиваются. Обрыв между
  получением ответа и записью в кэш может привести к повторной оплате.
- После трёх некорректных ответов API на замер опыт останавливается; отклонённые
  ответы остаются в состоянии.
- `api.max_requests` ограничивает число ответов API. Рубли и расход субагентов
  программа не считает; денежные лимиты задаются в сервисах.
- Модель, настройки и `session_id` субагента проверяются по данным, которые
  передал оркестратор; независимой проверки среды нет. Общий каталог не изолирует
  файлы: участнику передаётся только его запрос.
